## [Unreleased]

### Добавлено
- Settings → Postgres → «Перевести на свой Postgres…» для проектов на внешнем Postgres (стенд пользователя).
  Приложение поднимает свой контейнер `bm-<проект>-db` в своей сети, копирует базы сборок, пересоздаёт живые сборки.
  После этого остановка или удаление стенда ветки не ломает. Базы в прежнем Postgres остаются.

### Исправлено
- Если внешний Postgres проекта остановлен, Start, Restart и сборка ветки сначала запускают его контейнер. Раньше odoo
  ветки бесконечно перезапускался с ошибкой `could not translate host name "db"`.
- Формы Settings показывали списки (защищённые БД и контейнеры, переменные окружения) пустыми. Если добавить в такое
  поле значение и сохранить, прежний список заменялся одним новым значением.

## [0.2.0] — 2026-09-28

### Добавлено
- Пресет «Odoo в Docker»: для проекта нужен только git-репозиторий. Приложение само поднимает официальный образ
  `odoo:<версия>` (17.0, 18.0, 19.0 — версия определяется по манифестам) и свой Postgres проекта в Docker
  (`postgres.mode: managed`, контейнер `bm-<проект>-db`, порт только на 127.0.0.1). Postgres и образ готовятся сразу
  после создания проекта и удаляются вместе с проектом.
- Odoo Enterprise в пресете «Odoo в Docker»: папка с репозиторием `odoo/enterprise` или клонирование по адресу (одна
  ветка нужной версии). Аддоны монтируются только для чтения, в новые БД ставится `web_enterprise`.
- Мастер добавления проекта клонирует репозиторий по адресу. Для приватного репозитория — «Войти через браузер»
  (Git Credential Manager) или токен доступа. Учётные данные хранит Git в хранилище Windows, приложение их не
  сохраняет. SSH-адреса работают с ключами пользователя.
- Кнопка «Войти» в баннере ошибки fetch, если пропал доступ к репозиторию.
- Адрес репозитория может быть локальным или сетевым bare-репозиторием (`file:///…`); remote-папка вашего клона
  подставляется в мастер в таком виде.
- Экран приветствия проверяет Git и Docker и даёт ссылки на установку.

### Изменено
- Код сборок берётся с GitHub через собственную копию репозитория приложения (`repos\<имя>.git`). Ваш репозиторий
  приложение больше не трогает: ветки в нём можно свободно переключать, пока идут сборки. Все папки веток — detached,
  `tracking` в настройках больше нет.
- Ветка Development может брать код из вашей папки (Editor → «Из моей папки»): Restart показывает правки без коммита,
  коммит в папке запускает обновление сборки. Приложение папку только читает.
- Fork создаёт новую ветку на GitHub (push), а не локальную ветку в вашем репозитории.
- Мастер добавления проекта берёт адрес репозитория (введённый или из вашей папки) и загружает свою копию; выбирать
  папку для клона больше не нужно.
- «Удалить проект…» удаляет проект полностью: кроме сборок и папок веток — копию репозитория, compose-файлы, логи,
  файл настроек (без копии `.deleted-…`) и записи задач, аудита и исключений в реестре.
- **Проекты, добавленные раньше, нужно удалить и добавить заново**: для них сборки, fetch и Fork отключены, приложение
  показывает об этом баннер.
- Production без папки бэкапов собирается с чистой БД и вашими модулями, а не падает с ошибкой «Не найден бэкап
  прода». С заданной папкой бэкапов поведение прежнее.
- Мастер проверяет подключение к существующему Postgres до создания проекта.
- Фоновые fetch никогда не открывают окна входа Git, а ошибка доступа описывается понятно.

### Исправлено
- Без установленного Git мастер сообщал «Папка не является git-репозиторием». Теперь — «Git не найден» со ссылкой на
  установку.

## [0.1.3] — 2026-09-28

### Добавлено
- Проверка обновлений по релизам GitHub: при запуске (через 8 с, отключается в Settings → Приложение → Обновления) и
  вручную — в Settings, по ссылке в нижней строке окна и в меню трея. О новой версии сообщают баннер с описанием
  релиза и уведомление Windows. Версию можно пропустить.
- Установка обновления: после подтверждения установщик скачивается и проверяется по размеру и SHA-256 из релиза.
  Затем приложение полностью закрывается и запускает установщик. Если идут задачи, приложение спрашивает: дождаться
  их или прервать. Portable-версия вместо установки открывает страницу релиза.

## [0.1.1] — 2026-09-28

### Изменено
- Приложение переименовано в **Odoo Branch Manager**. Папки `%APPDATA%\DEMZ Branch Manager` и
  `%LOCALAPPDATA%\DEMZ Branch Manager` при первом запуске переносятся под новое имя вместе с проектами, реестром и
  логами. Если старую версию ещё не закрыли, приложение продолжает работать со старыми папками.
- AppUserModelId и appId установщика: `ua.bakum.odoo-branch-manager`. Уведомления Windows приходят от нового имени.

### Добавлено
- Система версий: единая версия во всех `package.json`, `pnpm release <patch|minor|major>`, проверка
  `pnpm version:check`. В сборку встраиваются версия, коммит и дата сборки. Они видны в нижней строке окна, на
  странице Status и в `main.log`.
- Строка внизу окна: версия и «© Bakum Viacheslav». Копирайт записан и в свойства установщика.

## [0.1.0] — 2026-09-28

Этап 1 (MVP) по ТЗ `branch-manager-spec.md`. Проверка критериев приёмки — в `docs/acceptance.md`.

### Добавлено
- Electron-оболочка: main, Core в `utilityProcess`, renderer в sandbox. Связь только через MessagePort, без
  HTTP-порта. Один экземпляр, трей, уведомления Windows, запрет сна во время сборок, баннер Docker Desktop.
- Мастер первого запуска и мастер добавления проекта с автоопределением. Пресеты DEMZ и Generic Odoo.
- Настройки по уровням (приложение → проект → стадия → правило → ветка): формы и YAML-редактор со схемой,
  уровень-источник у каждого поля.
- Стадии Production / Staging / Development, правила веток, автодобавление, перетаскивание, Fork (без push).
- Сборки: очередь и лимиты, шаги 8.3, зеркало прода из `.zip` с нейтрализацией и `postRestore`, копии БД через
  `TEMPLATE`, `fresh`, `update` на новый коммит (fetch и локальный HEAD), «Повторить с шага», «Отбросить», DROPPED.
- Traefik на `*.localhost`, compose-проект на ветку, метки `bm.*`, согласование с реестром при старте, сироты.
- Вкладки ветки: History, Shell, Editor, Logs, Backups, Tools (Debug, `launch.json`), Settings. Страницы Builds, Status,
  Audit Logs.
