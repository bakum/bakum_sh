# Задача: реализовать DEMZ Branch Manager — этап 1 (MVP)

Ты реализуешь десктопное приложение «локальный odoo.sh» для Windows по готовому ТЗ.

## Источник правды

- ТЗ: `branch-manager-spec.md` в корне репозитория (`E:\bakum_sh`). Прочитай его **целиком** до написания кода.
  Копия в `E:\demz-odoo-19\docs\` может устареть — не используй её.
- Если по ходу работы выяснится, что ТЗ неточно или неисполнимо, не молчи: исправь `branch-manager-spec.md` и запиши
  причину в `docs/decisions.md`.
- Объём работ — **только этап 1** (раздел 12 ТЗ). Готовность = критерии приёмки из раздела 13. Функции этапов 2–3 не делай,
  но не закрывай им дорогу: схемы настроек (раздел 9) описывай полностью, а в UI недоступные функции показывай
  отключёнными с пометкой «этап 2».
- Fork в MVP — без push. Кнопка «Push -u origin» относится к этапу 2.

## Решения уже приняты — не пересматривай

Electron, а не Tauri и не веб-сервер. Три процесса: main, Core в `utilityProcess`, renderer в sandbox. Связь только по IPC
через MessagePort, **HTTP-порта у приложения нет**. Odoo открывается во внешнем браузере. У ветки одна живая сборка,
предыдущие переходят в DROPPED. Модель стадий, правил веток и уровней настроек — как в ТЗ. Пресет DEMZ: Production =
`19.0`, Staging = `19.0-demz-crm` и `19.0-demz-prerelease`, Development = копия зеркала прода и `onNewCommit: update`.

## Жёсткие ограничения безопасности (нарушение = провал задачи)

1. Не подключаться ни к чему, кроме локального Docker и Postgres на `localhost:5433`. Настоящий прод недоступен и не нужен.
2. Никогда не останавливать, не пересоздавать и не менять контейнеры `odoo19`, `odoo19-db` и БД `o19_test`, `postgres`.
   Удалять можно только ресурсы, которые приложение само создало и записало в реестр: метки `bm.*`, БД по шаблону
   `naming.db`, каталоги внутри `worktreesDir`.
3. В репозитории `demz-odoo` разрешено: `git fetch`, `git worktree add/remove`, `git branch` (создание; удаление — только
   `-d` по явному действию пользователя), `git checkout --detach` внутри worktree приложения. Запрещено: push, изменение
   веток на `origin`, любые операции в основном чекауте, кроме перечисленных. Сейчас основной чекаут на ветке
   `19.0-demz-perevertum` — не переключай его.
4. Все внешние команды — через `execa` с массивом аргументов, без shell-строк. SQL-идентификаторы — только из шаблонов
   с проверкой `^[a-z0-9_]+$`.
5. Для ручных проверок во время разработки используй отдельный проект-песочницу с префиксом БД `o19_bmdev_` и хостами
   `{slug}.dev.localhost`. Реальный пресет DEMZ запускай только на финальной проверке критериев.

## Инженерные правила

- TypeScript strict везде. `packages/core` не импортирует `electron`: весь десктоп живёт в `apps/desktop`,
  а Core получает зависимости через интерфейсы (уведомления, открытие путей и т. п. — событиями в main).
- IPC-контракт — zod-схемы в `packages/shared`. Типы выводятся из схем, входящие сообщения валидируются в Core.
- Каждый шаг сборки идемпотентен и допускает повтор (`IF EXISTS`, проверка существования worktree, контейнера, каталога).
  Перед каждым destructive-вызовом — проверка по реестру и защищённым спискам (отдельная функция `assertOwned()`
  с unit-тестом).
- Слияние уровней настроек (раздел 9.1) — чистая функция, которая возвращает значение и уровень-источник для каждого поля.
- Unit-тесты Vitest (под `ELECTRON_RUN_AS_NODE=1`): slug (включая примеры из 8.2), шаблоны имён и переменные 9.2,
  слияние уровней, выбор стадии по `branchRules`, определение модулей и разделение `-u` / `-i` (8.7), парсинг логов Odoo,
  `assertOwned()`, генерация `compose.yml` (снапшот).
- Логи — `pino` в `<dataDir>/logs/`, лог каждой сборки — отдельный файл. Сообщения об ошибках для пользователя — по-русски,
  с понятным следующим шагом.
- UI на русском, Mantine, тёмная и светлая темы. Внешний вид и раскладка — как odoo.sh (раздел 6 ТЗ).

## Когда спрашивать пользователя

Спрашивай только если решение destructive, выходит наружу или противоречит ТЗ так, что выбор меняет архитектуру.
Всё остальное решай сам в духе ТЗ и записывай в `docs/decisions.md`: контекст, решение, альтернатива.
