## [Unreleased]

### Добавлено
- «Войти как…» в меню кнопки CONNECT, как Connect as на odoo.sh: список внутренних пользователей базы сборки с

## [0.13.18] — 2026-10-02

- В истории сборок (вкладка History ветки) вместо первой буквы автора — его аватар с GitHub, как на odoo.sh.

## [0.13.17] — 2026-10-01

### Изменено
- Skill для ассистентов (Settings проекта → «Ассистенты») теперь прямо говорит работать в сборке своей ветки: ветка —

## [0.13.16] — 2026-10-01

### Исправлено
- После того как у ветки выключили «Из моей папки», «Применить» поднимало сборку на старом коде: worktree приложения
  оставался на коммите, где был до работы из папки, хотя сборка числилась собранной на новом. Модули ветки Odoo не
  находил («not installable»), а приложение ошибки не показывало. Теперь «Применить», Start, Restart, ручные модули и
  тесты, а также повтор сборки с середины сначала переводят worktree на коммит сборки. Если в worktree есть правки
  или коммита сборки нет на GitHub, задача отказывает с объяснением и ничего не затирает. Если worktree всё-таки
  стоит на другом коммите, на странице ветки появляется красная плашка с кнопкой «Применить».

## [0.13.15] — 2026-10-01

### Исправлено
- Когда Docker Desktop не запущен, ветка со сборкой больше не горит зелёным: её состояние показывается как

## [0.13.14] — 2026-09-30

### Исправлено
- После перезагрузки Windows Status мог показывать «Нет подключения к Postgres localhost:55432 ()», хотя сборки
  работали. Windows (Hyper-V / WSL) зарезервировала блок портов с 55432, и Docker не смог опубликовать порт
  Postgres приложения. Теперь приложение само переносит Postgres на свободный порт и сохраняет его в настройках
  проекта; сборок это не касается. Новые проекты получают порт из диапазона 15432–15531, который Windows не
  резервирует. В сообщении об ошибке подключения теперь видна причина.

## [0.13.13] — 2026-09-30

### Исправлено
- Импорт большого бэкапа `.zip` (Rebuild Production из бэкапа) падал на шаге database с
  `OSError: [Errno 12] Cannot allocate memory`: Docker Desktop не справлялся с чтением архива из папки Windows. Теперь
  архив распаковывает само приложение: база загружается из `dump.sql` потоком в `psql`, filestore распаковывается
  прямо в папку сборки, затем идёт нейтрализация, как раньше. В build.log виден прогресс загрузки `dump.sql`, а во
  временной папке контейнера больше не оседает копия базы (у бэкапа DEMZ — 9 ГБ).

## [0.13.12] — 2026-09-30

## [0.13.11] — 2026-09-30

### Изменено
- Ветка «Из моей папки» блокируется, если в папке открыта другая ветка (переключили в IDE, идёт rebase): сборка
  больше не обновляется сама кодом чужой ветки, Rebuild, Retry, Start, Restart, «Применить», модули, тесты (в

  папке. Блокировка снимается сама, как только в папке снова открыта нужная ветка.

## [0.13.10] — 2026-09-30

### Изменено
- History ветки: по 5 сборок на страницу, число сборок и пагинатор — над лентой (и под ней), без прокрутки вниз.

### Исправлено
- В репозитории без `__pycache__` в `.gitignore` после первой сборки ветки Rebuild отказывал («есть незакоммиченные
  изменения»), новый коммит ставил ветку на паузу, а удаление ветки просило подтвердить потерю правок: байткод Python,
  который пишет Odoo, считался правкой пользователя. Теперь `__pycache__` и `*.pyc` не учитываются.
- Действия со сборкой (Shell, Terminal, логи, удаление, перезапуск после прерывания) искали контейнер только по номеру
  сборки и при двух профилях приложения (например, dev и рабочем) могли найти контейнер другого проекта. Теперь
  контейнер ищется по проекту и номеру сборки.

## [0.13.9] — 2026-09-30

### Изменено
- Если Fork не смог создать ветку на GitHub, диалог не закрывается и объясняет причину: Git не вошёл в GitHub, у
  учётной записи (названа по имени) нет права на запись, правила репозитория не разрешают такое имя или нет
  соединения. Под каждый случай — что сделать; для входа по https — кнопка «Войти и повторить» с окном Git Credential

  Write.
- README: раздел «Доступ к GitHub» — чьи учётные данные использует приложение и что делать при отказе.

## [0.13.7] — 2026-09-30

### Изменено
- Настройка «Удалять вместе с веткой на GitHub» переименована в «Удалять, если ветку удалили на GitHub»: прежнее
  название читалось как «удалить ветку и на GitHub». Смысл не изменился — после fetch приложение удаляет у себя ветку,
  которой больше нет на GitHub; саму ветку на GitHub приложение не удаляет никогда. В Settings ветки у настройки
  появилось пояснение, диалог удаления ветки напоминает, что ветку на GitHub нужно удалить самому.
- Диалог «+» у стадии объясняет, что он делает: подключает ветку, которая уже есть на GitHub (новую ветку создаёт
  Fork). После выбора ветки он пишет, начнётся ли сборка сразу и какая будет база (копия какой ветки или чистая). Если
  добавлять нечего, вместо пустого списка — «Все ветки репозитория уже добавлены». При `autoAddBranches: all` (как у
  DEMZ) сказано, что новые ветки с GitHub приложение добавляет само при fetch, а под «+» бывают только ветки, удалённые
  из приложения. У «+» появилась подсказка «Добавить существующую ветку с GitHub».

## [0.13.6] — 2026-09-29

### Исправлено
- Ветка, чей PR влит в `19.0` merge-коммитом, больше не считается отстающей от кода копируемой БД: если код ветки

## [0.13.5] — 2026-09-29

### Исправлено
- После удаления сборки, ветки или проекта в Docker оставался анонимный том контейнера Odoo (`/var/lib/odoo`, около
  8 МБ), если контейнер хоть раз пересоздавался (новая сборка, «Применить», Rebuild). Теперь такие тома удаляются
  вместе со сборкой. Тома, оставшиеся от прежних версий, удалите вручную: `docker volume ls -f dangling=true`, затем
  `docker volume rm <том>`.

## [0.13.4] — 2026-09-29

## [0.13.0] — 2026-09-29

### Добавлено
- Командная строка `bm` для ассистентов и скриптов: `bm status`, `bm modules <ветка> -u …`, `bm test <ветка> <модули>`,
  `bm restart <ветка>`. Работает, пока приложение запущено; команды идут задачами очереди (видны в History и Audit

  Лежит в `%LOCALAPPDATA%Odoo Branch Managerin` (`bm.cmd` — cmd / PowerShell, `bm` — Git Bash), Node не нужен.
- Тесты выбранных модулей по запросу: вкладка ветки Tools → «Запустить тесты» или `bm test`. Идут на временной копии
  базы сборки, как тесты при сборке; итог — в бейдже Test и `tests.log`.
- Skill для ассистентов использует `bm` как основной способ; после обновления нажмите «Обновить» в Settings проекта →
  «Ассистенты».

### Исправлено

## [0.10.0] — 2026-09-29

### Изменено
- Папки модулей для `addons_path` сборки берутся из кода её ветки: новая переменная `{addonsPath}` в

## [0.9.1] — 2026-09-29

### Изменено
- После выката на прод ветки Development, собранные из копии зеркала прода, различаются. Если в ветке есть код прода,
  баннер говорит «Зеркало прода обновилось — Rebuild возьмёт свежую копию». Если ветка отстаёт от `19.0`, баннер

  как такая, её можно удалить.
- Rebuild отстающей ветки спрашивает подтверждение, а в `build.log` сборки пишется, какие модули обновятся более
  старым кодом.

## [0.9.0] — 2026-09-29

Завершение этапа 2 ТЗ: проверка всех его возможностей — в `docs/acceptance.md`, раздел «Приёмка этапа 2». Отложены
почта сборок (Mailpit), создание PR через `gh` и хуки сборок.

### Добавлено
- Сборка образа Odoo из Dockerfile (`runtime.build`): Settings → Рантайм → «Сборка образа Odoo из Dockerfile».
  Приложение собирает образ перед сборками веток и при «Применить», правка Dockerfile помечает живые сборки
  «конфигурация изменилась». Кнопка «Собрать образ сейчас» проверяет Dockerfile заранее и показывает лог.
- Приложение не перезаписывает образ, собранный не им (например, образ вашего docker-compose): для своего образа
  предлагается тег `bm-<проект>-odoo:latest`. Удаление проекта удаляет и собранный для него образ.

## [0.8.0] — 2026-09-29

### Добавлено
- Вкладка Monitor: CPU и память сборки за последний час, запросы в минуту и время ответа, ошибки 5xx, размер БД и
  filestore, последний заход, когда сборка остановится и до какого числа её хранить. Графики с подсказками и таблица
  значений.
- `idleStopHours` работает: живая сборка, к которой столько часов не было запросов, останавливается (Start поднимает
  её снова). Фоновые запросы открытой вкладки Odoo заходом не считаются.
- `dropAfterDays` — срок хранения: по его истечении приходит уведомление «Сборку можно отбросить», бейдж в History
  становится красным. Сама сборка не удаляется.
- CONNECT ▾ → «Отбросить сборку…» для живых сборок Development.

### Изменено
- Traefik пересоздаётся один раз: его лог теперь ограничен по размеру (приложение читает его, чтобы видеть заходы в
  сборки).
- Почта сборок через Mailpit отложена. Вкладка Mails и Settings → «Почта» объясняют, почему письма из сборок наружу
  не уходят, и предупреждают не включать почтовый сервер вручную в сборке с копией прода.
- Создание PR через `gh`, удаление ветки в origin и хуки сборок отложены: пометки «этап 2» у них убраны, Merge
  открывает страницу сравнения на GitHub, вкладка «Хуки» говорит, что раздел `hooks` пока не выполняется.

  импортировать в Production.
- Снапшоты удаляются вместе со своей БД: при отбрасывании сборки, новой сборке ветки, удалении ветки или проекта.

## [0.6.0] — 2026-09-29

### Добавлено
- `cloneMethod: dump`: копия БД через `pg_dump` / `pg_restore` без остановки сборки-источника (медленнее, чем
  `template`, зато зеркало прода продолжает работать). Выбирается в настройках стадии или ветки.

  следующем запуске.

## [0.2.0] — 2026-09-28

### Добавлено
- Пресет «Odoo в Docker»: для проекта нужен только git-репозиторий. Приложение само поднимает официальный образ
  `odoo:<версия>` (17.0, 18.0, 19.0 — версия определяется по манифестам) и свой Postgres проекта в Docker
  (`postgres.mode: managed`, контейнер `bm-<проект>-db`, порт только на 127.0.0.1). Postgres и образ готовятся сразу
  после создания проекта и удаляются вместе с проектом.
- Odoo Enterprise в пресете «Odoo в Docker»: папка с репозиторием `odoo/enterprise` или клонирование по адресу (одна
  ветка нужной версии). Аддоны монтируются только для чтения, в новые БД ставится `web_enterprise`.
- Мастер добавления проекта клонирует репозиторий по адресу. Для приватного репозитория — «Войти через браузер»
  (Git Credential Manager) или токен доступа. Учётные данные хранит Git в хранилище Windows, приложение их не
  сохраняет. SSH-адреса работают с ключами пользователя.
- Кнопка «Войти» в баннере ошибки fetch, если пропал доступ к репозиторию.
- Адрес репозитория может быть локальным или сетевым bare-репозиторием (`file:///…`); remote-папка вашего клона
  подставляется в мастер в таком виде.
- Экран приветствия проверяет Git и Docker и даёт ссылки на установку.

### Изменено
- Код сборок берётся с GitHub через собственную копию репозитория приложения (`repos\<имя>.git`). Ваш репозиторий
  приложение больше не трогает: ветки в нём можно свободно переключать, пока идут сборки. Все папки веток — detached,
  `tracking` в настройках больше нет.
- Ветка Development может брать код из вашей папки (Editor → «Из моей папки»): Restart показывает правки без коммита,
  коммит в папке запускает обновление сборки. Приложение папку только читает.
- Fork создаёт новую ветку на GitHub (push), а не локальную ветку в вашем репозитории.
- Мастер добавления проекта берёт адрес репозитория (введённый или из вашей папки) и загружает свою копию; выбирать
  папку для клона больше не нужно.
- «Удалить проект…» удаляет проект полностью: кроме сборок и папок веток — копию репозитория, compose-файлы, логи,
  файл настроек (без копии `.deleted-…`) и записи задач, аудита и исключений в реестре.
- **Проекты, добавленные раньше, нужно удалить и добавить заново**: для них сборки, fetch и Fork отключены, приложение
  показывает об этом баннер.
- Production без папки бэкапов собирается с чистой БД и вашими модулями, а не падает с ошибкой «Не найден бэкап
  прода». С заданной папкой бэкапов поведение прежнее.
- Мастер проверяет подключение к существующему Postgres до создания проекта.
- Фоновые fetch никогда не открывают окна входа Git, а ошибка доступа описывается понятно.

### Исправлено
- Без установленного Git мастер сообщал «Папка не является git-репозиторием». Теперь — «Git не найден» со ссылкой на
  установку.
